# Алина

Личный AI-помощник: отдельный сайт с тёмной и светлой темой, чатом, историей, редактируемой памятью и голосом. Подготовлен для Railway. Для одного пользователя.

## Что уже реализовано

- Вход по личному паролю; закрытые API, HttpOnly-сессии и ограничение попыток входа.
- Переключатель темы, адаптация для телефона и компьютера.
- Несколько разговоров и история в SQLite.
- Раздел «Память»: вы сами выбираете, какие сведения учитывать во всех разговорах.
- Текстовые ответы OpenAI Responses API, модель `gpt-4.1-mini`.
- Голосовой ввод по кнопке: до 60 секунд, `gpt-4o-mini-transcribe`. Распознанный текст можно проверить до отправки.
- Озвучивание ответов по кнопке: `gpt-4o-mini-tts`, голос `shimmer`. Для длинного ответа озвучиваются первые 1500 символов; это отмечено на кнопке. Голос синтетический.
- Серверная квота запросов, проверка длительности записи, защита от параллельных платных запросов.

## Запуск на Railway

1. В Railway создайте проект → **Deploy from GitHub repo** → `khshavkatov-star/Alin`.
2. Добавьте к сервису **Volume** с путём монтирования `/data`. В этой папке хранится SQLite. Без Volume история, память и счётчик квоты могут потеряться при пересоздании контейнера.
3. В **Variables** задайте:

| Переменная | Значение |
|---|---|
| `APP_PASSWORD` | Ваш уникальный длинный пароль, минимум 12 символов |
| `OPENAI_API_KEY` | Отдельный ключ проекта OpenAI с оплаченным API |
| `DATA_DIR` | `/data` |
| `AI_MONTHLY_QUOTA_USD` | `30` |

`PORT` Railway задаёт автоматически. `NODE_ENV=production` уже указан в Dockerfile; не отключайте его на публичном сайте — он включает Secure cookie.

4. Запустите Deploy. Railway автоматически использует Dockerfile.
5. В **Settings → Networking** выберите **Generate Domain**. Открывайте сайт по HTTPS: это нужно для защищённой сессии и микрофона.
6. Войдите с вашим `APP_PASSWORD`. Отправьте короткое сообщение, затем проверьте запись и озвучивание. Реальная доступность моделей зависит от API-проекта.
7. Оставьте **одну реплику**: эта версия рассчитана на один процесс и один Volume. Настройте резервное копирование Volume средствами Railway.

Без `APP_PASSWORD` сервер отказывается запускаться. Без `OPENAI_API_KEY` интерфейс и память работают, но ответы и голос недоступны; это явно указано в интерфейсе.

## Бюджет до $50 в месяц

Рабочий ориентир: до $10 на Railway, до $30 на OpenAI, $10 резерва. Это план, а не обещание фиксированного счёта. Проверьте тариф своего Railway workspace: базовый платёж Pro отличается от Hobby.

### Что означает «Квота AI»

Это **внутренний консервативный счётчик**, а не фактические списания OpenAI:

| Действие | Списывается из внутренней квоты |
|---|---:|
| Один текстовый запрос | $0.05 |
| Распознавание записи до 60 секунд | $0.03 |
| Озвучивание до 1500 символов | $0.10 |

Сумма резервируется **до** обращения к API. При ошибке или таймауте резерв остаётся: неизвестно, обработал ли провайдер запрос. Повторное воспроизведение уже загруженного ответа в текущей странице бесплатно; повторная генерация — новый запрос.

По достижении квоты новые AI-запросы блокируются, история и память остаются доступны. Счётчик хранится в Volume и сбрасывается по календарному месяцу UTC. Значение ограничено $30 в коде для согласованного бюджета. Суммы резерва не являются тарифами моделей. Квота не учитывает другие приложения, API-ключи и расход Railway; она не гарантирует общий счёт ровно до $50.

Для финансового контроля используйте отдельный API-проект/ключ, небольшой предоплаченный баланс без автоматического пополнения и доступные ограничения расходов Railway. Уведомления о бюджете могут не останавливать расход; проверьте поведение лимитов в кабинетах провайдеров. Не считайте установленными настройки, которые ещё не включили сами.

## Данные и ограничения первой версии

- Репозиторий содержит только код. Не добавляйте в GitHub ключи, пароль, `.env` или папку `data`.
- Разговоры и память находятся в SQLite на вашем Railway Volume. Сама SQLite не шифрует содержимое; доступ владельцев Railway к диску не ограничивается паролем приложения.
- Для ответа в OpenAI передаются ваше сообщение, сохранённая память и ограниченный контекст текущего разговора (до 20 сообщений, суммарно до 10 000 символов). Старые сообщения остаются в истории, но модель не получает всю историю целиком.
- Для Responses API используется `store: false`. Это не обещание отсутствия технических журналов у провайдера; учитывайте его правила обработки данных.
- Аудиозапись отправляется на сервер и в OpenAI для распознавания; приложение не сохраняет исходную запись в базу.
- Память сохраняется вручную в разделе «Память». Автоматическое извлечение фактов, интернет-поиск, Google Таблицы, напоминания и управление компьютером пока не подключены.
- Кнопка «Новый разговор» сохраняет старые разговоры. Функции удаления истории в первой версии нет.
- Смена `APP_PASSWORD` и перезапуск аннулируют старые сессии. Один пароль рассчитан на одного владельца.
- Микрофон работает только по кнопке; нет постоянного прослушивания и активации по слову «Алина».

## Локальный запуск

Требуется **Node.js 24+**. Внешних npm-зависимостей нет.

```bash
cp .env.example .env
# Заполните APP_PASSWORD и OPENAI_API_KEY в локальном .env.
# Для локального запуска задайте DATA_DIR=./data вместо /data.
node --env-file=.env server.mjs
```

Откройте `http://localhost:3000`. Локально `NODE_ENV` не должен быть `production`, поскольку локальный HTTP не поддерживает Secure cookie.

```bash
npm test
```

Тесты используют подставной ответ API и не расходуют деньги. Проверяют авторизацию, защиту запросов, восстановление данных, квоту, валидацию аудио и ошибки провайдера. Реальную речь и ответы необходимо проверить после добавления API-ключа.
